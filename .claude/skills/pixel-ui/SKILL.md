# Pixel UI — 薪水小偷視覺規範

方向:**p10k 風深色終端機裡的打卡機**。不是 Game Boy、不是 NES 紅白機
—— 是工程師開一整天不傷眼的深色終端機。這個選擇來自主題本身:
app 假裝是辦公軟體,所以復古的是「辦公軟體」而不是「遊戲機」。

## 鐵律(違反 = 破壞產品)

1. **`Disguise.tsx`(假 Excel)永遠保持現代樣貌。** 偽裝殼的唯一工作是
   看起來像真的公司軟體,像素化它等於自爆。它不 import 全域 pixel 樣式
   之外的東西沒關係,但絕不套用像素字型、像素邊框、掃描線。
2. **老闆鍵切換瞬間不能有過場動畫。** 偽裝要快,tween 會害死使用者。
3. 隱私與資料規則不變(見 PLAN.md)—— 視覺改版不碰資料層。

## 字型

繁中像素字型用 **fusion-pixel-font**(TakWolf,SIL OFL,支援繁中),
12px proportional zh_hant 變體。像素字型只在**整數倍**尺寸下乾淨:
12 / 24 / 36 / 48px,text size 全部貼齊這些檔位,不要用 14px、20px 這種
會糊掉的尺寸。數字與金額可搭配等寬變體對齊。

**現行檔位**(v8,base 從 12 提到 24):內文 24px、密集區與徽章(團隊列、
熱力圖圖例、辦公室名牌)12px、標題 36px、主畫面大數字 48px(sm 以上 72px)。
Tailwind 的 `text-sm`(14)、`text-xs` 之外的預設檔位大多不在格上,**一律
寫成 `text-[24px]` 這種明確值**,不要用 `text-sm/lg/xl`。大數字刻意不跟著
內文翻倍——它本來就夠大,再翻一倍窄螢幕會爆版。唯一例外是 `Disguise.tsx`
(鐵律 1:假 Excel 要現代臉,不受這套檔位管)。

**次要文字走 `--px-small` 這一個旋鈕**(index.css):`.px-small`、`.px-btn`、
`.px-input` 都吃它。值是**手機 18px / 桌機(≥640px)12px**。

18 是**刻意違反格線的例外,不要「順手修正」回 12 或 24**:使用者實測後的
結論是 12 在手機上看不清、24 又太大,而 12 與 24 之間沒有乾淨檔位 ——
知道它會微糊,仍然選它。要調整就改 `--px-small` 那一行,不要把尺寸散回
各元件。

## CSS 像素技法

- **邊框**:2px 實線,**零 border-radius**。立體感用 Win3.1 斜角:
  `border-color: 亮 暗 暗 亮`(凸起),按下時反轉(凹陷)。
- **陰影**:硬位移零模糊 `box-shadow: 3px 3px 0 <深色>`,絕不用 blur。
- **縮放點陣圖 / SVG 圖塊**:`image-rendering: pixelated`。
- **進度條**:分段方塊(repeating-linear-gradient 或格子),不要平滑漸層。
- **掃描線**:全螢幕 overlay,repeating-linear-gradient,透明度 ≤ 0.06,
  `pointer-events: none`。這是氛圍不是主角。
- 調色盤紀律:全 app ≤ 7 色(定義在 index.css 的 @theme),新 UI 不准
  引入盤外顏色。**唯一例外是辦公室場景內部**(見下方「角色與 sprite」)。

## 動畫

- **CSS `steps()` 優先** —— 像素風的動作本來就該一格一格跳,這正是
  steps() 的語意,免費且免依賴。游標閃爍、精靈步伐、打字機效果都是它。
- **面板展開用 `clip-path` 由上往下揭開,不要 `scaleY`**(`.px-unroll` 是
  先例):scaleY 會在中間的格數把字壓扁,clip-path 讓內容原地不動、只是還沒
  露出來 —— 那才是「一張紙從板子上捲下來」。六格 240ms,開視窗要是幾格跳完
  的,不是滑進來的。
- 真的需要 tween/timeline(彈性、物理、複雜編排)才用 GSAP —— skills
  已裝(gsap-core / gsap-react / gsap-timeline),npm 套件**等真的要用
  才裝**,不要因為 skill 在就先裝。
- 尊重 `prefers-reduced-motion`;辦公室走位與金額跳動是功能不是裝飾,
  可保留,裝飾性動畫要能關。

## 角色與 sprite

角色定義在 `office/sprite.ts`、家具在 `office/props.ts`,**全部 ASCII 手繪**
(一個字母一個代號),跟 `map.ts` 同一個慣用法。要改就改字串。

- **尺寸**:一格 16 art 像素、畫面放大 2 倍(`PIXEL`)。角色 16×24(1.5 格高),
  家具寬是整數格、可以往上超出一格。**家具和角色必須同一個像素密度** —— 用螢幕
  像素畫的東西擺在 2 倍像素的角色旁邊,就是拼貼感。
- **角色組合**:頭(髮型 × 方向)疊身體(方向 × 走路格)。正背面左右對稱,
  跨步 B = A 鏡像;側面只畫朝右,朝左用 `scaleX(-1)`。
- **畫法**:深色描邊(`k`,角色與家具共用同一條輪廓色)+ 每種材質兩階明暗。
  暗色手調成對寫,不要用程式算 —— 算出來的會偏灰、沒有色相偏移。
- **場景調色盤(v13 起)**:辦公室**裡面**(地板、牆、家具、角色)是一個世界,
  有自己的盤,寫在 sprite.ts / props.ts,**不走 `var(--color-crt-*)`、不跟主題換色**。
  舊規則(角色只准用 UI 7 色)正是角色看起來敷衍的原因,已翻轉,理由見 PLAN v13。
  辦公室**外框**(名牌、狀態列、按鈕)照舊只用 7 色。
- **每人一張臉**:`lookFor(userId, avatar)`。沒自訂就由 userId 雜湊;自訂存在
  `profiles.avatar`(6 碼選項編號,換裝面板是 `office/Wardrobe.tsx`)。選項清單
  **只能往尾巴加**:DB 存的是索引,重排會讓舊存檔解成別的樣子。
- **畫成 inline SVG,不要改成 PNG / sprite sheet。** 顏色是每個人不同的
  palette swap,形狀全場共用;圖檔做不到這件事,還要在 repo 放二進位檔。
  節點數用 `runs()` 橫向合併壓下來,Actor 用 memo 擋住 Office 每 100ms 的重畫。
- **深度排序**:家具 z = 底邊列 × 10、角色 z = 腳底 y × 10,同一條軸。
- **走路格由「實際移動距離」驅動**,不是 CSS animation、也不是按鍵狀態 ——
  面壁推不動時腳不會空踩,走走停停時腳步跟位移同步。
- 眨眼、螢幕閃、盆栽搖這類**裝飾**照舊是 CSS `steps()`,掛 class 在對應代號的
  色塊上(props.ts 的 `anim`),並列入 reduced-motion 關閉清單。

## 已像素化 / 不像素化清單

- 像素化:計數器、設定、摸魚報告、團隊、辦公室的「介面外框」。
- 辦公室場景(地板、家具、角色)本來就是像素邏輯,用場景盤(見上)。
- 不像素化:Disguise.tsx(見鐵律)、分頁 title/favicon 的偽裝行為。
